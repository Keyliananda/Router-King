# Process Note 2026-03-14 12:00

## Scope

Dieser Stand fasst den kompletten unstaged Worktree zusammen, der am 14.03.2026 in einen Sammel-Commit übernommen wurde.
Der Schwerpunkt lag auf zwei Themen:

1. Ausbau der RouterKing-AI mit Actions, Tool-Prompting und besserer Modell-/Client-Logik.
2. Sicherheits- und Robustheitsverbesserungen im GRBL-Sender für einen echten Maschinen-Test.

## Enthaltene Änderungen

### AI / Assistant

- `RouterKing/ai/actions.py` neu:
  Zentrale Action-Ausführung für Geometrie, Sketches, CAM und Maschinenbefehle.
- `RouterKing/ai/assistant.py` erweitert:
  Primitive-Erzeugung aus Prompts, Hilfe-/Tool-Antworten, CAM-Analyse/Job-Start-Helfer und LLM-Action-Blöcke.
- `RouterKing/ui/main_dock.py` erweitert:
  AI-Setting `Allow AI actions`, Modellnamen-Bereinigung ohne Kosten-Suffixe, Action-Weitergabe an den Chat-Worker.
- `RouterKing/ai/client.py` angepasst:
  Besseres Modellrouting für Responses-/Chat-Verhalten und `max_completion_tokens` bei Reasoning-Modellen.
- `tests/test_ai_assistant.py` erweitert:
  Hilfe-/Tool-Prompt-Pfad abgedeckt.

### GRBL / Maschinensteuerung

- `RouterKing/grbl/sender.py` gehärtet:
  Verbindungsaufbau prüft jetzt aktiv auf echte GRBL-Antwort.
- Streaming verwendet echte GRBL-Realtime-Kommandos:
  `Pause` -> `!`, `Resume` -> `~`, `Stop` -> Soft Reset / Abort.
- Serial-Abbrüche markieren den Sender sauber als getrennt und liefern einen Disconnect-Grund zurück.
- `RouterKing/ui/main_dock.py` abgesichert:
  Jobstart nur bei bekannter `Idle`-Maschine, sauberer Disconnect-State bei Linkverlust.
- Im G-Code-Tab gibt es jetzt einen expliziten `Dry Run`-Schalter:
  Beim Streamen werden `M3/M4/M5` aus dem Sendepfad entfernt.
- `RouterKing/gcode/parser.py` und `RouterKing/gcode/__init__.py` erweitert:
  Hilfsfunktionen für Dry-Run-Filtering vor dem Streamen.
- Neue Tests in `tests/test_grbl_sender.py`.
- `tests/test_gcode_parser.py` um Dry-Run-/Spindel-Filterfälle erweitert.

### Doku / Sonstiges

- `README.md` wurde parallel deutlich erweitert und von der knappen MVP-Beschreibung auf eine ausführlichere Produkt-/Feature-Darstellung umgestellt.
- `docs/temp/20260207-temp.md` enthält einen temporären CAM-Risk-Check-Log.

## Sicherheitsrelevante Korrekturen vor dem Push

Vor dem Commit wurde ein versehentlich im Default-Config-Wert eingetragener OpenAI-API-Key in `RouterKing/ai/config.py` wieder entfernt.
Der Default steht wieder auf leerem String; ENV-Overrides bleiben unverändert aktiv.

Außerdem wurde ein bestehender Syntaxfehler in `RouterKing/ai/assistant.py` korrigiert, damit der Sammel-Commit keinen offensichtlichen Import-Bruch enthält.


Ergebnis:

- Sender-/Parser-/CAM-relevante Tests laufen grün.
- `./scripts/test.sh` läuft nach den Korrekturen wieder ohne Importfehler durch.
- Hinweis: `tests/test_ai_pricing.py` bleibt in pytest-artigem Stil geschrieben, wird vom aktuellen `unittest discover`-Setup importiert, aber nicht als `unittest`-Testklasse ausgeführt.

## Offene Punkte

- Die neue AI-Action-Schicht ist funktional eingebunden, braucht aber noch gezielte End-to-End-Tests in echter FreeCAD-Session.
- Für reale Maschinenfahrten sind weiterhin Bedien-Disziplin, Homing und Freiraumprüfung Pflicht; der neue `Dry Run` reduziert Risiko, ersetzt aber keine Maschinenfreigabe.
