# Process Note 2026-05-16 10:56

## MCP CAM Existing-Feature Readiness Audit

### Gewaehlter Mini-Schritt

Vorhandene CAM-Generate-Faehigkeiten nicht neu bauen, sondern direkt ueber MCP
parametrierbar machen.

### Befund

RouterKing nutzt CAM bereits an mehreren Stellen:

- UI-Generate mit `generate_hybrid_gcode`
- FreeCAD CAM/Path-Job-Erzeugung mit Simple-Fallback
- Operationen `profile`, `pocket`, `drilling`
- CAM- und Simple-Fallback-Defaults in FreeCAD Preferences
- DXF-to-GCode ueber FreeCAD/ezdxf/basic-parser
- GRBL-Postprocessing und CAM-Risikoanalyse

Die MCP-Oberflaeche war fuer Generate noch zu eng, weil direkte Tools nur
`model`, `operations`, `output_path`, `prefer_cam` und `use_cam_defaults`
beworben haben.

### Umsetzung

- `routerking_generate_gcode` und `routerking_cam_generate_job` nehmen jetzt
  vorhandene CAM/Path-Settings direkt an:
  `post_processor`, `feed_rate`, `plunge_rate`, `start_depth`, `final_depth`,
  `step_down`, `profile_side`, `profile_direction`.
- Vorhandene Simple-Fallback-Settings sind ebenfalls direkt erreichbar:
  `safe_z`, `start_z`, `cut_z`, `pass_depth`, `ramp_length`, `lead_in`,
  `lead_out`, `units`, `spindle_speed`, `laser_power`, `start_spindle`.
- `machine_profile_path` ist fuer vorhandenes GRBL-Postprocessing direkt im
  Generate-Tool-Schema sichtbar.
- `routerking_cam_capabilities` nennt die direkt unterstuetzten
  Generate-Settings.

### Tests

- stdio-Schema-Tests pruefen die neuen CAM-/Simple-Generate-Parameter.
- Wrapper-Tests pruefen, dass die Parameter in die Action-Payloads gelangen.

### Offene Folgepunkte

- CAM-G-Code-Analyse als direktes MCP-Tool.
- DXF-to-GCode als direktes MCP-Tool.
- Strukturierte Generate-Ergebnisse (`engine`, `output_path`, `warnings`,
  optional `job_id`).
- CAM-Workbench-Status/Aktivierung als MCP-Diagnose.
