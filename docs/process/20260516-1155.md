# Process Note 2026-05-16 11:55

## CAM Stepdown Persistence

### Befund

FreeCAD CAM setzt Pocket-Operationen standardmaessig ueber SetupSheet-
Expressions. Im getesteten Job war `StepDown` an `OpToolDiameter` gebunden,
also bei einem 5-mm-Werkzeug automatisch 5 mm. Direkte Werte auf der Operation
wurden dadurch bei Recompute wieder ueberschrieben.

### Umsetzung

- RouterKing entfernt vor expliziten CAM-Property-Overrides die entsprechenden
  FreeCAD-Expressions.
- Quantity-artige FreeCAD-Properties werden ueber `.Value` gesetzt, bevor auf
  normales `setattr` zurueckgefallen wird.
- Das Job-SetupSheet bekommt bei explizitem `StepDown` eine Laengen-Expression
  wie `1 mm`, damit spaetere CAM-Aktualisierungen nicht wieder auf
  `OpToolDiameter` zurueckfallen.
- Pocket-Operationen bekommen ein explizites `StepOver`.
- Die konservativen Defaults fuer kleine GRBL-/Bambus-Pocket-Arbeit wurden auf
  `feed_rate=500`, `plunge_rate=150`, `step_down=0.5`, `step_over=35`,
  `pass_depth=0.5`, `ramp_length=8` und `spindle_speed=10000` gesetzt.

### Live-Job

Der offene FreeCAD-Job `RK_Back_Pocket_Setup` wurde korrigiert:

- `SetupSheet002.StepDownExpression = "1 mm"`
- `Back_Pocket_4mm.StepDown = 1.0 mm`
- Der Toolpath enthaelt danach vier Z-Ebenen: `Z19`, `Z18`, `Z17`, `Z16`.

### Tests

Neue CAM-Hybrid-Tests pruefen Quantity-Property-Assignment, Expression-Clearing,
Pocket-Property-Overrides inklusive `StepOver` und Warnungen bei nicht
angewendeten Properties.
