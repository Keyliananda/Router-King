# Process Note 2026-05-16 11:24

## MCP CAM Agent Tools

### Gewaehlter Mini-Schritt

Agenten sollen vor dem Maschinenpfad zwei vorhandene CAM-Faehigkeiten direkt
nutzen koennen: G-Code-Risikoanalyse und DXF-to-GCode.

### Umsetzung

- `routerking_cam_analyze_gcode` analysiert G-Code direkt im MCP-Server. Das
  Tool ist read-only, benoetigt keine FreeCAD-Verbindung und liefert
  `summary`, `stats` und strukturierte `issues`.
- `routerking_dxf_generate_gcode` erzeugt ueber die RouterKing-Action
  `dxf_generate_gcode` Simple-CAM-G-Code aus DXF. Der Action-Pfad bleibt
  absichtlich erhalten, weil optional Dateien geschrieben und die G-Code-UI
  aktualisiert werden koennen.
- Die DXF-Action nutzt vorhandene `DxfImportSettings` und `SimpleJobSettings`.
  Maschinensteuerung bleibt getrennt und weiterhin nur ueber die bestehenden
  Machine-Tools moeglich.

### Feature-Nutzen

Ein Agent kann jetzt einen CAM-Ablauf ohne manuelle UI-Bedienung vorbereiten:

1. vorhandene CAM-Setups/Operationen inspizieren,
2. G-Code aus Modell oder DXF erzeugen,
3. G-Code analysieren,
4. danach erst postprocessen, validieren und bei expliziter Freigabe streamen.

### Tests

- MCP-Schema-Tests pruefen beide neuen Tools.
- Wrapper-Tests pruefen direkte Analyse und DXF-Action-Payloads.
- Bridge-Tests pruefen Required-Field-Validierung und Modify-Transaction fuer
  DXF.
- DXF-Tests pruefen direkte DXF-G-Code-Erzeugung und den strukturierten
  Action-Handler-Pfad.

### Offene Folgepunkte

- Strukturierte Generate-Ergebnisse fuer `generate_gcode` und
  `cam_generate_job`.
- CAM-Workbench-Status/Aktivierung als eigene MCP-Diagnose.
- Danach realer Projekt-Test mit FreeCAD, vorhandenen CAM-Setups und
  mindestens einer echten DXF-Datei.
