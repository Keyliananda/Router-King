# Process Note 2026-05-16 10:45

## MCP CAM Support Iteration 3

### Gewaehlter Mini-Schritt

Eine einzelne CAM-Operation detailliert ueber MCP inspizierbar machen, ohne
FreeCAD-Dokument, CAM-Job, Toolpaths, Postprocessing oder Maschine zu veraendern.

### Contextbudget-Schaetzung

- `input_tokens_estimate`: mittel, weil die vorhandenen Setup-/Operation-
  Serializer und Tests wiederverwendet wurden.
- `output_tokens_estimate`: mittel, da ein neues Tool inklusive Diagnostics,
  Wrapper, Schema, Tests und Doku ergaenzt wurde.
- `safety_margin`: ausreichend, weil mutierende CAM-Tools weiter ausgeschlossen
  bleiben.

### Umsetzung

- `RouterKingBridge.cam_inspect_operation()` ergaenzt.
- Operation-Lookup per `operation_id`, optional eingegrenzt durch `setup_id`.
- Ambigue Operation-IDs liefern Matches statt eine zufaellige Operation zu
  inspizieren.
- Detailantwort mit Setup-Kontext, Base-Details, Property-Status, Path-Summary,
  begrenztem G-Code-Auszug und Diagnosewarnungen.
- MCP-Wrapper, Registry und stdio-Schema ergaenzt.

### Tests

- Bridge-Tests fuer Detailantwort und Missing-Operation-Fehler ergaenzt.
- Wrapper-Test fuer Parameterweitergabe ergaenzt.
- stdio-Schema-Test fuer required `operation_id` und read-only Filter/Flags
  ergaenzt.

### Roadmap und Doku

- `docs/concepts/ai/MCP_TOOLS.md` dokumentiert das Tool als read-only und
  side-effect-frei.
- `docs/roadmap/20260516-1021-mcp-cam-support.md` markiert Iteration 3 als
  erledigt.

### Offene Folgepunkte

Naechster sinnvoller Schritt ist `routerking_cam_create_setup`, damit ein Agent
nach der Inspektion gezielt ein neues Setup anlegen kann, ohne sofort G-Code zu
postprocessen.
